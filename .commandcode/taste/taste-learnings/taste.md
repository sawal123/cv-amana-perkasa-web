# Taste Learnings
- Communicates in Indonesian (Bahasa Indonesia); replies and explanations should be written in Indonesian, keeping technical terms/framework names in English. Confidence: 0.85
- Reaches for MySQL as the default relational database when planning a backend, rather than Postgres/SQLite — treat MySQL as the assumed target unless told otherwise. Confidence: 0.75
- Normally builds APIs in Laravel, but treats it as too heavy for small projects because it forces a separate codebase; for small sites he wants the backend/API and admin living inside the same repo as the frontend. Frame architecture proposals accordingly — lead with the single-repo option, and only suggest Laravel when the project genuinely warrants it. Confidence: 0.85
- Opens work by asking for an assessment of an existing project ("cek project saya ini") before any code is written — inspect the real config/files first, state what blocks or enables the request, then propose options and wait for a pick. Confidence: 0.55
- Wants claims proven against real infrastructure, not just static checks: approved ("continue") a long verification sequence that spun up Docker with actual MySQL 8 + MariaDB containers and drove the admin panel in a real browser, and installed the requested browser-automation tool (agent-browser) rather than skipping the write-path tests or falling back to a fragile HTTP probe. Budget for and default to end-to-end verification (real DB, real browser, seed/migrate round-trips, re-run after each fix) instead of stopping at `tsc --noEmit` + build. Confidence: 0.7
- When offered a choice of verification approaches, picks the option labelled "(Recommended)" — surface a single recommended path with the trade-offs spelled out rather than an undifferentiated menu. Confidence: 0.5
